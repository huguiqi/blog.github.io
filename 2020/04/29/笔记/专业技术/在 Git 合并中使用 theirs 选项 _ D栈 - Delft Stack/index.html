在 Git 合并中使用 theirs 选项

创建时间: April-22, 2022

  1. 在 Git 中将 git merge 命令与 theirs 一起使用
  2. 使用 --strategy-option 解决 Git 中的冲突
  3. 在 Git 中使用临时分支进行合并

在使用 Git 工具开发软件时，你可以为不同的功能创建不同的分支。但是不同分支之间可能存在冲突。

本文将解释如何使用带有 theirs 选项的 git merge 命令来解决冲突。

在 Git 中将 git merge 命令与 theirs 一起使用

git merge 命令可以合并两个或多个开发历史。但是，由于分支之间的冲突，有时无法完成此合并。

ours 或 theirs 中的文件应丢弃以解决此冲突。

ours 是指具有 Git 历史权限的原始工作分支，theirs 是指包含新应用提交的分支。

你可以使用 git merge -s ours 丢弃 ours 中的更改。此命令会丢弃来自其他分支的所有更改，并使你分支上的文件保持不变。

当你下次从另一个分支合并时，Git 只会考虑从这一点开始所做的更改。但是，-s 选项不能与 theirs 一起使用。

使用 --strategy-option 解决 Git 中的冲突

或者，我们可以将 theirs 与 -X 或 --strategy-option 选项一起使用。

-X 和 -s 选项之间的主要区别在于 -X 执行常规递归合并，使用所选一侧解决任何冲突，而 -s 将合并更改为完全忽略另一侧。

以下命令使用 theirs 解决任何冲突。

Copygit merge -X theirs branchname

在 Git 中使用临时分支进行合并

使用下面的命令将 test2 合并到签出的 test1 中。

切换到 test1 分支。

Copygit checkout test1

合并提交而不会发生冲突。ours 的内容稍后将被丢弃。

Copygit merge -s ours test2

创建一个临时分支。

Copygit branch temp

使用 git reset 命令设置 HEAD。它从 test2 分支获取内容。

Copygit reset --hard test2

重置为合并提交，但使用 git reset --soft 命令保留内容。

Copygit reset --soft temp

用 test2 的内容更改合并提交的内容。

Copygit commit --amend

删除我们之前创建的临时分支。

Copygit branch -D temp

你可以看到合并后的提交仅包含 test2 的内容。

Copygit diff HEAD test2
